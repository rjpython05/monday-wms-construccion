Evidencia AC-01-09 — Branch protection en main
Fecha: 2026-10-03

Contexto (CHG-003): GitHub devuelve 403 "Upgrade to GitHub Pro or make this
repository public to enable this feature" para branch protection clásico Y para
rulesets en un repo privado de cuenta individual. Verificado en vivo contra la
API real, no por memoria. El RT eligió hacer el repositorio público.

Configuración aplicada (PUT /repos/rjpython05/monday-wms-construccion/branches/main/protection):
  required_status_checks: strict=true, contexts=[Pipeline, Escaneo de secretos
    (historial completo), Auditoría de dependencias (SCA)]
  enforce_admins: true
  required_pull_request_reviews: required_approving_review_count=0
    (ver RSK-012: no hay segundo humano disponible; Auditor IA compensa manualmente)
  allow_force_pushes: false
  allow_deletions: false
  required_linear_history: true
  required_conversation_resolution: true

Verificación real (push directo a main como el propio admin, después de aplicada
la protección):

  $ git push
  remote: error: GH006: Protected branch update failed for refs/heads/main.
  remote:
  remote: - Changes must be made through a pull request.
  remote:
  remote: - 3 of 3 required status checks are expected.
  ! [remote rejected] main -> main (protected branch hook declined)

Conclusión: push directo rechazado incluso para el admin (enforce_admins=true).
AC-01-09 verificado salvo por "≥1 revisión humana", que queda documentado como
no exigible por GitHub en un equipo de una persona (RSK-012) y compensado
manualmente por el Auditor IA.
